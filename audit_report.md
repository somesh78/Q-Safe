# Q-Safe Codebase Audit Report

## 1. CRITICAL ISSUES (breaks core functionality)

### Nginx Reverse Proxy Points to Non-Existent Internal Localhost
- **File:** `nginx.conf`
- **Line:** 12 & 24 (`proxy_pass http://127.0.0.1:8000;`)
- **Issue:** Nginx is configured to forward requests to `127.0.0.1` inside the Docker network. Within the `q_safe_nginx` Docker container, localhost refers to the Nginx container itself, not the Django container. All API and WebSocket requests will fail with a 502 Bad Gateway.
- **Root cause:** Docker network isolation mismatch.
- **Fix required:** Change the proxy statements to `proxy_pass http://web:8000;` based on the alias defined in `docker-compose.yml`.

### WebRTC Race Condition During Transfer Finalization
- **File:** `frontend/src/pages/P2PSend.jsx` / `frontend/src/pages/P2PReceive.jsx`
- **Line:** ~791 in `P2PSend.jsx` (`peer.channels[0].send(...)`)
- **Issue:** WebRTC SCTP multiplexes data over multiple independent channels (e.g., `file-0`, `file-1`). The sender blasts file chunks across these parallel channels, but immediately upon loop completion, it sends `{"type": "transfer_complete"}` on `channel 0`. Because delivery between sibling data channels is not synchronized, the termination signal can arrive before in-flight chunks on parallel channels, causing the receiver to prematurely trigger `finalize()` and fail file reconstruction entirely.
- **Root cause:** Operating under the assumption that multi-channel WebRTC data delivery is globally ordered.
- **Fix required:** In `P2PSend.jsx`, implement a `waitingForAcks` state or have the receiver verify `receivedBytesRef.current >= fileMeta.size` before executing `finalize()`. 

### Django Admin UI Broken by Global Static Interception 
- **File:** `backend/backend/settings.py`
- **Line:** 348 (`STATIC_URL = '/'`)
- **Issue:** Setting `STATIC_URL` to root intercepts all Django-generated static references without a prefix (e.g., `/admin/css/base.css`). WhiteNoise will attempt to resolve this as a static file, but `urls.py` captures `/admin/` first, leading to conflicting namespace resolution and breaking the Django admin styling.
- **Root cause:** Attempting to overlay React's root-static topology onto Django's global static asset mechanism.
- **Fix required:** Restore `STATIC_URL = '/static/'` and configure WhiteNoise explicitly for React overrides using `WHITENOISE_ROOT`.

## 2. FLOW GAPS (steps in a user journey that are broken/missing)

- **Flow:** Online File Storage ➔ Celery Cleanup
  - **Missing step:** There is no Celery beat job or scheduled task to clean up expired `OnlineEncryptedFile` data if nobody downloads them. 
  - **Impact:** While files are deleted upon max downloads, files that reach their `expires_at` threshold without being downloaded will persist in Supabase indefinitely, leading to runaway cloud storage costs.

- **Flow:** Offline Mode Scanning ➔ File Decryption
  - **Missing step:** "Receiver scans without internet -> file received". The backend provides an endpoint `reconstruct_from_zip` (in `views.py`) that handles ZIP unpacking, QR decoding, and file stitching. If the offline receiver uses this backend API to parse the ZIP generated by the sender, it completely nullifies the "without internet" requirement. 
  - **Impact:** True offline decryption is impossible unless `reconstruct_from_zip` logic is entirely ported into the client-side React code (e.g., `Reconstruct.jsx`). 

## 3. DISCREPANCIES (frontend/backend contract mismatches)

- **Frontend expects Boolean, Backend parses String**
  - **File locations:** `P2PSend.jsx` (Upload payload) / `transfers/views.py` (Line 155)
  - **Discrepancy:** The frontend API service serializes configurations (like `enableIpLock: true`). In Django, DRF parses this (in multipard form-data) as the string `"true"`. The backend logic `request.data.get("enable_ip_lock") == "true"` correctly anticipates a string, but if the client ever transmits it as JSON boolean `True`, the comparison fails. Ensure uniform serialization enforcement.

- **Hardcoded Global WebRTC Chunk Sizes Ignore Logic**
  - **File locations:** `P2PSend.jsx`
  - **Discrepancy:** Global constants like `CHUNK_SIZE_LAN = 1024 * 1024` are explicitly defined at the top of the file, but entirely ignored in the target scope. Later in `sendFile()`, chunk limits are blindly re-declared inline `const CHUNK_SIZE = isLAN ? 256 * 1024 : ...`. 

## 4. SECURITY VULNERABILITIES

| Severity | File | Issue | Recommended fix |
|---|---|---|---|
| **High** | `transfers/views.py` | **IP Lock Authentication Bypass.** The IP lock logic relies on `elif encrypted_file.allowed_ip != ip and encrypted_file.download_count > 0`. A malicious actor attempting a password brute force won't increment the `download_count` until successful, meaning the IP lock never engages against them. | Disengage the `download_count > 0` condition from the explicit `allowed_ip != ip` check. |
| **High** | `P2PSend.jsx` & `P2PReceive.jsx` | **TURN Server Credentials Leaked.** The `ICE_SERVERS` block hardcodes the username (`qsafe`) and password (`QSAFE_SECURE_PASSWORD_123!`) on the frontend. Attackers can hijack this TURN instance for proxying their own torrent/relay traffic. | Implement a backend endpoint returning time-limited (ephemeral) TURN credentials using a shared secret HMCA. |
| **Medium** | `transfers/consumers.py` | **Unauthenticated WebSocket Proxy.** `P2PSignalingConsumer` inherits `AsyncWebsocketConsumer` with no JWT binding. Anyone can use the signaling server to establish an arbitrary pub-sub room, representing a DoS vector. | Enforce standard Django Channels authentication context inside `connect()` ensuring only registered/whitelisted JWT holders can signal. |

## 5. PERFORMANCE / STABILITY RISKS

- **File:** `transfers/views.py` (`reconstruct_from_zip` and `upload_file`)
  - **Issue:** RAM Exhaustion via String loading. Files in `upload_file` (configured up to 500MB via `ONLINE_MAX_FILE_SIZE_MB`) are entirely loaded into instance memory using `encrypt_file_chunks(...)` before handing execution to Supabase `storage.upload_file()`. Similarly, `OfflineJob` generation reads gigabytes of encrypted binary logic into continuous memory allocations.
  - **Potential impact:** Immediate out-of-memory (OOM) crashing for the worker upon handling a concurrent heavy load (EC2 typical 1GB restriction broken immediately).

- **File:** `transfers/views.py`
  - **Issue:** `zipfile.ZipFile(zip_file)` processes images in `reconstruct_from_zip` explicitly one at a time via `qr_decode`, blocking the synchronous thread indefinitely.
  - **Potential impact:** High CPU thrashing and complete worker starvation logic.

## 6. DEAD CODE / UNUSED FEATURES

- **`ContactMessage` View Bindings:** The model `ContactMessage` is defined in `transfers/models.py` but possesses no associated `serializers`, routing, or views. It operates as an entirely severed database node.
- **Unreachable WebSocket Cleanup Logics:** In `P2PSend.jsx`, WebRTC candidates that trigger timeouts drop connection references prematurely without clearing bounded event listeners from `dc.onopen`, exacerbating a hidden frontend memory leak on repetitive transfers.

## 7. PRIORITY FIX ORDER

1. **[S] Nginx Reverse Proxy Networking Fix:** Application cannot process ANY requests until `127.0.0.1` binds exclusively to the internal Docker `web` alias container.
2. **[S] IP Lock Bypass Resolution:** Mitigates immediate security threat masking brute-force operations.
3. **[M] WebRTC Transfer_Complete Race Condition:** Implement synchronized `receivedBytesRef` to eliminate failing P2P transfers on disparate networks.
4. **[M] Abstract TURN Credentials:** Protect expensive outgoing EC2 bandwidth from exploitation.
5. **[S] Celery Cleanup Integration:** Create an automated task routing through `OnlineEncryptedFile` queries mapping instances where `expires_at < timezone.now()`.
6. **[L] Implement Streaming Encryption Processing:** Refactor the buffer ingestion to utilize multipart generators, significantly reducing worker OOM limits.
